# 未修的工具缺陷与假阴性

本文件只列**仍未解决**的工具问题：报了错、报成「没有」、或语义容易误读的行为。修掉的条目直接删掉，不留档案——结论在提交信息里，仍然成立的做法写进 [workflow](workflow.md) 或技能文件的禁令，本文件不承担历史记录。

ROM 结论、补丁方案、游戏相关地址一律不写在这里。

## 判据与分级

| 字段 | 含义 |
|------|------|
| 编号 | `TI-nnn`，稳定编号，不复用；编号不连续说明中间那些已经修掉并删除 |
| 症状 | 调用方直接看到的现象 |
| 证据 | 可复现的命令或调用序列；标 `实锤` / `推测` |
| 影响 | 会让人做出什么错误决定 |
| 状态 | 未修 / 第三方（不在本项目可改范围） |
| 绕行 | 修掉之前必须怎么做 |

**假阴性比报错更危险**：报错会让人换路，报「没有」会让人据此排除整类方案。

## TI-008 客户端附件层拒收字节完全相同的截图

| 字段 | 内容 |
|------|------|
| 症状 | 连续两次取帧且画面未变时，图片结果被替换成 `durable image storage rejected the result` |
| 证据 | 实锤：同一帧重复取图即拒绝；推进若干帧或按住按键后再取即可 |
| 影响 | 会以为取图工具坏了，进而改用文本渲染代替截图——那会丢掉几何信息（楼梯、地形） |
| 状态 | 第三方（客户端附件层，不在本仓库与 MesenGM fork 内） |
| 绕行 | 两次取图之间必须改变画面；需要同一画面多次分析时，先按键或推帧再取 |

## TI-012 本地路径当 git 远端时命令不返回

| 字段 | 内容 |
|------|------|
| 症状 | `git ls-remote ./x.git`、`git fetch origin <本地路径>` 这类命令一直不返回，无输出也无退出码；同一时刻对 https 远端的 `git fetch` 秒回 |
| 证据 | 实锤（症状）：本地路径的 `ls-remote` 与 `fetch` 在 60 s / 8 s 内无任何输出，只能强杀；对 https 远端同样的 `fetch` 立即完成。原因推测：git 的本地传输会派生 `upload-pack` 之类的子进程并通过管道通信，本运行环境的管道限制让它卡住 |
| 影响 | 把本地路径写进测试夹具或核验脚本会让整轮挂死；被强杀的 git 会留下进程，占住仓库句柄，之后删除目录报 `EPERM`、写索引报 `unable to write new index file` |
| 状态 | 第三方（git 在本运行环境下的行为，不在本仓库代码内） |
| 绕行 | 要远端证据就用 https URL；纯本地判断用 `for-each-ref`、`branch -r --contains`、`cat-file -e`，不要 fetch。测试夹具不要用本地路径当远端——`tests/pin.test.mjs` 的失败分支指向一个非仓库目录，git 不开传输就拒绝。挂死之后先清进程：`Get-Process git* \| Stop-Process -Force` |

## 记录规则

- 新增条目：先有可复现判据，再写影响；没有判据的只写「推测」。
- 修掉之后：删掉条目。仍然成立的排错顺序、禁令或工具事实改写进 [workflow](workflow.md) 或技能文件的硬性禁止，不留在本文件。
- 第三方问题：状态写「第三方」，注明卡在哪一层，绕行照旧有效。
- 不写游戏名、ROM 名、具体 RAM 地址与存档路径；用 `<addr>`、`<状态字段>` 之类的占位符。
